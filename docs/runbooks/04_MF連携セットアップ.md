# 04 MF 連携セットアップ（MF 側の登録と Script Properties）

`docs/実装設計_MF連携.md`（以下「設計書」）の WP-M1〜M3 を本番で動かすために、
**マネーフォワード（MF）側で登録・設定するもの**と、その結果を GAS に入れる手順。
MF の画面名・手順は 2026-10-08 に MF 公式サポートの各ページで確認した（出典は各節末尾）。
画面は更新されることがあるため、食い違ったら出典ページを開き直す。

- 作成日: 2026-10-08
- 前提: パーソナルミニプラン（アプリプランではない）。事業者情報は 2026-09-01 に設定済み
  （`docs/未決事項・デプロイ前確認.md` §6.8）。OAuth 用の連携アプリは 2026-09-01 の疎通スパイクで
  作成済みの見込み（`CLIENT_SECRET_BASIC` を実測した記録がある）

## 全体像（依存の順序）

```
A. アプリポータルの利用開始・権限（1 回きり）
   ├─ B. 請求書 API: 連携用アプリ（Client ID / Secret、リダイレクト URI）
   │     └─ D. 初回認可（ローカルスクリプト）→ MF_INVOICE_TOKENS
   │           └─ E. 取引先・部署の登録 → department_id を API で読む → MF_DEPARTMENT_ID
   └─ C. 会計 API: API キー → MF_ACCOUNTING_API_KEY、事業者番号 → MF_OFFICE_CODE
F. 請求書 → 会計の連携設定（会計連動）
G. GAS の Script Properties とフラグ（最後。フラグは段階ごとに有効化）
```

B〜C は A が済めば並行してよい。E は D のトークンを使う。

## A. アプリポータルの利用開始と権限

アプリポータルは、連携用アプリ（OAuth）の登録と API キーの発行を行う MF の画面。登録・利用は無料。

1. 管理コンソールで「全権管理」権限を持つユーザー（本人）で、アプリポータルにアクセスする
2. 「マネーフォワード IDでログイン」→ 利用規約と個人情報の取扱いに「同意する」→ 利用開始する事業者の「選択」
3. 「ユーザー」画面で自分を選び、「編集」で次の権限にチェックを入れて「保存」
   - **アプリ開発**（連携用アプリの登録に必要）
   - **アプリ連携**（OAuth の認可操作に必要。対象サービスで「クラウド請求書」を選ぶ）
   - 権限を付与できるのは「システム管理」権限を持つユーザー。利用開始したユーザーに
     「システム管理」が付くかどうかは公式ページに記載がない（[未検証]。「ユーザー」画面で
     自分の権限を見れば決着する）
4. API キーの発行には権限は不要（アプリポータルにユーザーとして登録されていればよい）

出典: [「アプリポータル」の利用開始方法](https://biz.moneyforward.com/support/app-portal/guide/g001.html)（2026-08-20 更新）、
[「権限」の設定方法](https://biz.moneyforward.com/support/app-portal/guide/g008.html)（2026-08-20 更新）、
[アプリポータルの概要（APIキー）](https://developers.biz.moneyforward.com/docs/common/api-keys/app-portal-overview/)

## B. 請求書 API: 連携用アプリ（OAuth）

9/1 のスパイクで作ったアプリがあれば**新規登録せず、そのアプリの設定を確認する**（アプリ詳細画面）。

1. クラウド請求書の「API連携（開発者向け）」画面で「APIの利用を開始する」を押す（未実施なら）
2. アプリポータルの「アプリ開発」画面 → 「新規登録」（既存アプリなら詳細画面で「編集」）
3. 入力項目
   | 項目 | 値 |
   |---|---|
   | アプリ名称 | `kadobo`（認可画面に表示される。100 文字以内） |
   | リダイレクト URI | **`http://127.0.0.1:8765/callback`**（`scripts/mf-oauth-authorize.mjs` が待ち受けるアドレス。`localhost` ではなく `127.0.0.1` で登録する。複数登録できるので、スパイク時の URI が残っていても追加でよい） |
   | クライアント認証方式 | **`CLIENT_SECRET_BASIC`**（`invoiceClient.ts` は Basic 認証で実装している） |
4. 利用規約に同意して「登録」→ 「アプリ詳細」画面の **Client ID** と **Client Secret** を控える
   （Secret は「再発行」できる。再発行したら GAS の `MF_CLIENT_SECRET` も差し替える）

出典: [連携用アプリを登録する](https://biz.moneyforward.com/support/app-portal/guide/g011.html)（2026-08-19 更新）、
[クラウド請求書API スタートアップガイド](https://biz.moneyforward.com/support/invoice/guide/api-guide/a04.html)（2026-01-09 更新）

## C. 会計 API: API キーと事業者番号

### C-1. API キーの発行

1. アプリポータルの「APIキー管理」画面 → 「新規登録」
2. 「APIキー名」に `kadobo`、「利用可能サービス」で **「事業者情報」と「クラウド会計・確定申告」**の 2 つにチェック
   （会計 API を API キーで使うにはこの 2 つが必要。他のサービスは選ばない）
3. 利用規約に同意して「登録」→ **表示された API キー（`mf_api_prd_…`）をその場でコピー**
   → 「確認しました」
   - **API キーは一度しか表示されない。** 控え損ねたら削除して作り直す
4. API キーは発行したユーザー（本人）の権限で動く。会計側で本人が「仕訳（編集）」「会計帳簿（閲覧）」
   「連携サービスから入力（閲覧・編集）」「データ連携（閲覧）」「勘定科目（閲覧）」を持っていること
   （事業者を作成した本人は通常すべて持つ。[未検証]。403 が返れば権限不足）

### C-2. 事業者番号（`MF_OFFICE_CODE`）

形式は `XXXX-XXXX`（8 桁）。次のどこでも確認できる。

- クラウド会計・確定申告: 画面右上の「？」→ 「事業者番号」
- クラウド請求書: 画面右上の歯車 → 「事業者設定」→ 「事業者番号」
- 管理コンソール: 画面右上の事業者名 → 「事業者番号」

出典: [「APIキー管理」画面の使い方](https://biz.moneyforward.com/support/app-portal/guide/g017.html)（2026-08-25 更新）、
[クラウド会計APIについて](https://biz.moneyforward.com/support/tax-return/guide/others/ot09.html)、
[各サービスの事業者番号の確認方法](https://biz.moneyforward.com/support/guide/u06.html)（2026-07-06 更新）

## D. 初回認可（請求書 API のトークン）

設計書 §4.5・§11.5。B で控えた Client ID / Secret を使う。

```sh
MF_CLIENT_ID=... MF_CLIENT_SECRET=... node scripts/mf-oauth-authorize.mjs
```

1. 表示された認可 URL をブラウザで開き、MF にログインして承認する（scope は `mfc/invoice/data.write`）
2. スクリプトが標準出力に **JSON 1 行**を出す。これを GAS の Script Property **`MF_INVOICE_TOKENS`** に貼る
   （`generation: 1`・`refreshed_at` を含む。改変しない）
3. 待受は 5 分で打ち切られる。失敗したら最初からやり直す

## E. 取引先（A社）と部署の登録、`department_id` の取得

### E-1. クラウド請求書の画面で登録する

1. 「マスタ管理」→「取引先」→「取引先を追加」
2. 「取引先の新規追加」画面で入力して「追加」
   | 項目 | 値・注意 |
   |---|---|
   | 取引先名 | A社の正式名称（**必須**。請求書の宛名になる） |
   | 郵便番号・住所・電話 | 請求書に載せる宛先 |
   | 支払い期限 | **設定しなくてよい**（kadobo は請求書作成時に `due_date` を毎回指定する）。設定する場合は「土日祝日」を「**前営業日にずらす**」にして kadobo の計算（契約の「休日は前営業日」）と揃える |
3. 登録した取引先の「詳細」→「部門を追加」→「部門の新規追加」画面で入力して「追加」
   - 部門名（`person_dept`）は請求書の宛名の 2 行目になる。A社に部署名が無ければ空欄にできるかは
     画面で確認する（API の必須項目は `department_id` だけなので、部署は 1 つあればよい）

### E-2. `department_id` を API で読む

`department_id` は画面に表示されない。D のトークンで `GET /api/v3/partners` を呼ぶと、
取引先ごとに `departments[].id` が返る（OpenAPI v3.6.0 で確認）。

```sh
# MF_INVOICE_TOKENS の JSON から access_token を取り出して使う（1 時間で失効。切れていたら D をやり直すか、
# GAS の mfInvoicePing を 1 回実行して更新させた後に Script Property から読み直す）
ACCESS_TOKEN='...'
curl -s -H "Authorization: Bearer $ACCESS_TOKEN" \
  'https://invoice.moneyforward.com/api/v3/partners?per_page=100' \
  | python3 -c 'import json,sys; [print(p["name"], d["id"], d.get("person_dept")) for p in json.load(sys.stdin)["data"] for d in p["departments"]]'
```

表示された A社の部署の `id` を Script Property **`MF_DEPARTMENT_ID`** に入れる。

出典: [取引先の設定方法](https://biz.moneyforward.com/support/invoice/guide/master/ma01.html)（2026-09-25 更新）、
OpenAPI `GET /partners`（`data[].departments[].id`）

## F. 請求書 → 会計の連携設定（会計連動）

請求書を作ると、会計側に「売掛発生の仕訳」と「入金予定の仕訳」が連携される。設計書 §13 U5。

1. クラウド請求書の「帳票設定」→「会計連動」で次を確認する
   | 項目 | 設定 | 理由 |
   |---|---|---|
   | 請求書に対応した売掛発生の仕訳 | 「作成する」にチェック（**初期値で ON**。外れていないか確認） | 売上の計上 |
   | 請求書に対応した入金予定の仕訳 | 同上 | 入金の消込に使う |
   | 売上計上日 | **「前月末」**（初期値のまま） | 10 月分の請求書を 11/1 に作る運用で、売上日が 10/31 になる |
   | 取引先名に応じた補助科目 | 任意（初期値は作成しない） | 取引先が 1 社なので不要 |
2. クラウド会計の「自動で仕訳」→「請求書から入力」→「自動仕訳設定」→「全体設定」は、
   **初期値（仕訳候補を確認してから登録する）のままにする**。kadobo が作った請求書の仕訳を
   人が一度見る場所になる。「仕訳候補を確認しない」にはしない
3. 「仕訳入力の期間制限」に制限日付を設定していると連携されない。設定していないことを確認する

[未検証] API で作成した請求書でも画面作成と同じく連携されるか。S-M1 のテスト請求書で、会計側の
「請求書から入力」→「仕訳候補」に売掛発生の仕訳が出れば決着する（確認後にテスト請求書と仕訳候補を削除する）。
[未検証] kadobo は請求書作成時に `sales_date`（対象月末）を指定する。「売上計上日」の設定とどちらが優先されるか。
同じ S-M1 で仕訳候補の取引日を見れば決着する。

出典: [「請求書から入力」の設定方法](https://biz.moneyforward.com/support/account/guide/journal02/infoguideiv_temporary_journals-set_up.html)（2026-07-09 更新）、
[クラウド会計・確定申告との連携について](https://biz.moneyforward.com/support/invoice/guide/linkage02/li01.html)（2024-08-30 更新）

## H. 開業前の明細と開始残高（カード・口座の連携後、最初に 1 回）

開業日（2026-10-01）より前の明細は事業の取引ではない。MF 公式の案内（[開業時の「開始残高」の入力](https://biz.moneyforward.com/support/tax-return/journal-knowledge/sj01.html)、[「連携サービスから入力」画面の使い方](https://biz.moneyforward.com/support/tax-return/guide/journal02/jo01.html)）に従い、次の順で処理する。kadobo は `MF_SYNC_START_DATE` より前の明細に触らない。

1. 「連携サービスから入力」で **9/30 以前の明細をすべて「対象外」にする**（口座・カードとも）。対象外は「登録済一覧」→「明細一覧」から解除できる
2. 開業前の日付で**仕訳済み**になっている明細があれば、その仕訳を削除する（削除すると明細は自動で対象外になる）
3. 「設定」→「開始残高」に **開業日（10/1）時点**の残高を入れる
   | 科目 | 値 |
   |---|---|
   | 普通預金 | 10/1 時点の事業用口座の残高 |
   | 未払金 | 10/1 時点のカードの未払残高（9 月利用分＝10/26 の引落し額。9/13 の NISA を含む）。入れないと 10/26 の「未払金 ／ 普通預金」で未払金がマイナスになる |
   | 元入金 | 貸借の差額（資産 − 負債） |
   | 開業費 | 開業前の事業関連の支出があれば（任意償却。Excel 等で明細を管理し合計を入れる） |
4. 連携の「自動取得対象の開始日」が開業日以降になっていることを確認する（以後、開業前の明細が取り込まれない）

[未検証] 開始残高の未払金に 9 月利用分を入れる扱いは、MF 公式の開始残高の説明（負債を入れる）から導いたもので、個別の記帳方法として税理士の確認はしていない。
