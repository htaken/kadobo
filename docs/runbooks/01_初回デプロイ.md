## ② Slack アプリ作成

1. https://api.slack.com/apps → **Create New App → From an app manifest** → 本人ワークスペースを選択
2. 下記 manifest を貼る（`request_url` は後で ④ で差し替えるので今はダミーのままでよい）:

   ```yaml
   display_information:
     name: 稼働記録
   features:
     bot_user:
       # bot_user.display_name は @ユーザー名に変換されるため英数字・一部記号のみ（日本語不可）。
       # 表示名を日本語にしたい場合は作成後に App Home の Display Name で変更する。
       display_name: kadobo
       always_online: true
     slash_commands:
       - command: /kado
         url: https://example.invalid/slack/commands
         description: 稼働カードの投稿・再描画・累計表示
         should_escape: false
       - command: /keihi
         url: https://example.invalid/slack/commands
         description: 経費入力（自動化フェーズで提供予定）
         should_escape: false
   oauth_config:
     scopes:
       bot:
         - commands
         - chat:write
         - files:read
         - im:write
   settings:
     interactivity:
       is_enabled: true
       request_url: https://example.invalid/slack/interactivity
     org_deploy_enabled: false
     socket_mode_enabled: false
     token_rotation_enabled: false
   ```

3. **Basic Information → App Credentials → Signing Secret** を控える → `SIGNING_SECRET`
4. **OAuth & Permissions → Install to Workspace** で承認 → **Bot User OAuth Token（`xoxb-…`）** を控える → `BOT_TOKEN`
5. Slack で私用チャンネル **`#稼働記録`**（private）を作り、`/invite @稼働記録` で Bot を招待。
   - `CHANNEL_ID`: チャンネル名クリック → 一番下の Channel ID（`C…`）
   - `USER_ID`: 自分のプロフィール → その他 → メンバー ID をコピー（`U…`）

✅ 確認: `SIGNING_SECRET` / `BOT_TOKEN` / `CHANNEL_ID` / `USER_ID` の 4 つが埋まった。

## ③ Cloudflare（Worker）デプロイ

1. ログイン（ブラウザ認証）:
   ```
   ! cd /Users/takenouchiharuhi/projects/kadobo/worker && npx wrangler login
   ```
2. D1 データベース作成:
   ```
   ! cd /Users/takenouchiharuhi/projects/kadobo/worker && npx wrangler d1 create kadobo-journal
   ```
   出力の `database_id` を控える → `DATABASE_ID`
3. `worker/wrangler.jsonc` の `"database_id": "REPLACE_WITH_WRANGLER_D1_CREATE_OUTPUT"` を `DATABASE_ID` に置き換える（このファイル編集は伴走者に依頼可）。
4. マイグレーション適用（本番 D1）と共有シークレット生成:
   ```
   ! cd /Users/takenouchiharuhi/projects/kadobo/worker && npx wrangler d1 migrations apply DB --remote
   ! openssl rand -hex 32          # 出力を SHARED_SECRET として控える（GAS 側と同じ値を使う）
   ```
   次にシークレットを投入する。**`wrangler secret put` は値の入力プロンプトが出るため、
   Claude Code の `!`（非対話）では入力できない。通常のターミナル（Terminal.app 等）で実行すること**
   （`echo "値" | ...` は履歴・会話にトークンが残るので避ける）:
   ```
   cd /Users/takenouchiharuhi/projects/kadobo/worker
   npx wrangler secret put SLACK_SIGNING_SECRET   # ② の SIGNING_SECRET を入力
   npx wrangler secret put SLACK_BOT_TOKEN         # ② の BOT_TOKEN
   npx wrangler secret put GAS_SHARED_SECRET        # ③-4 の SHARED_SECRET
   npx wrangler secret put GAS_URL                  # まだ不明。ダミー https://script.google.com/pending を入れる
   ```
5. デプロイ:
   ```
   ! cd /Users/takenouchiharuhi/projects/kadobo/worker && npx wrangler deploy
   ```
   - **初回のみ**: アカウントに workers.dev サブドメインが無いと「register a workers.dev subdomain now?」と
     聞かれる。`!`（非対話）だと no になり失敗するので、ダッシュボード
     （`https://dash.cloudflare.com/<account_id>/workers/onboarding`）でサブドメインを 1 つ登録
     （アカウントに 1 つ・全 Worker 共通）してから上記を再実行する。対話ターミナルで `deploy` して
     `y` で登録してもよい。
6. 出力の `https://kadobo-worker.<subdomain>.workers.dev` を控える → `WORKER_URL`

✅ 確認: `GET WORKER_URL/` が 404（正常。POST 専用のため）。
```
! curl -s -o /dev/null -w "%{http_code}\n" https://kadobo-worker.<subdomain>.workers.dev/
```

✅ 確認: スプレッドシートに 7 シートができ、トリガーが 4 つ登録され、HMAC チェックが OK。

## ⑨ 経費フェーズ（`/keihi`）の準備・デプロイ

実装設計 経費フェーズ §10.1（デプロイ順）に対応。①〜⑧の基本システムが動いている状態から、
経費機能を**フラグを無効にしたまま**追加し、紙証憑のみで試験してから段階的に有効化する。

1. **フラグは全て無効の状態で入れる**（実装設計 §10.1 ステップ1）:
   - GAS の Script Property `ENABLE_EXPENSE`／`ENABLE_E_DOC` は**まだ設定しない**（未設定＝無効）。
   - D1 は次の migration 適用時に `enable_expense`／`enable_e_doc` が `'0'` で自動投入される
     （`worker/migrations/0002_expense_flags.sql` の `INSERT OR IGNORE`）。

2. **スプレッドシートを xlsx でバックアップする**（ファイル → ダウンロード → xlsx）。
   経費台帳の列移行（`migrateExpenseLedger`。既存 14 列 → 24 列）は実行前にヘッダー一致を
   確認し不一致なら中断する設計（fail closed）だが、必ず事前にバックアップを取ってから
   `setupSpreadsheet` を再実行すること。

3. **証憑ルートフォルダを手で作成する**（自動作成はしない。実装設計 §5.9）:
   - Google Drive で新規フォルダを作る（名前は任意）。
     **フォルダ名を「経費証憑」にしないこと。** GAS はこのフォルダの直下に
     `経費証憑/{紙|電子取引}/YYYY/MM` を初回保存時に自動生成する（`gas/src/adapters/drive.ts`）
     ため、フォルダ名を「経費証憑」にすると Drive 上のパスが二重（`経費証憑/経費証憑/紙/...`）になる。
   - フォルダを開き、URL の `/folders/<ここ>` を控える → `ROOT_FOLDER_ID`。
   - GAS エディタ（`npx clasp open-script`）→ スクリプト プロパティで
     `DRIVE_RECEIPT_ROOT_ID` に `ROOT_FOLDER_ID` を設定する。
   - サブフォルダ（`経費証憑`／`紙`／`電子取引`／年／月）は手で作らない。

4. **GAS をデプロイする**（`expense_submit` を受け取れる実装＋列移行。実装設計 §10.1 ステップ4）:
   ```
   ! cd /Users/takenouchiharuhi/projects/kadobo && npm run build
   ! cd /Users/takenouchiharuhi/projects/kadobo/gas && npx clasp push --force
   ```
   `clasp push` だけでは⑤-6 で発行した `/exec` デプロイには反映されない。既存デプロイを
   新バージョンへ更新する（`../02_運用・再デプロイ.md` §B と同じ手順）:
   ```
   npx clasp deployments                       # @<番号> の付いた方の deploymentId を確認
   npx clasp create-deployment --deploymentId <⑤-6 で発行したデプロイの ID> --description "経費フェーズ追加"
   ```
   続けて `setupSpreadsheet`（列移行）・`installTriggers`（週次トリガー追加）を GAS エディタから
   再実行する（すでに ⑤-7 で一度実行済みでも、冪等なので再実行してよい）。

5. **Worker をデプロイし、migration を remote に適用する**（実装設計 §10.1 ステップ5）:
   ```
   ! npm run -w @kadobo/worker test && npm run -w @kadobo/worker typecheck
   ! cd /Users/takenouchiharuhi/projects/kadobo/worker && npx wrangler d1 migrations apply DB --remote
   ! cd /Users/takenouchiharuhi/projects/kadobo/worker && npx wrangler deploy
   ```

6. **疎通試験**: フラグが全て無効のまま `/keihi` を実行する。
   ✅ 確認: モーダルは開かず、ephemeral
   「⚠️ 経費機能は無効になっています（フラグ `enable_expense`）。有効化するまで登録できません。運用手順に従って有効化してください。」が返る
   （§10.1 ステップ6。フラグが効いていることの確認）。

7. **紙証憑のみで有効化**（実装設計 §5.9.3: **有効化は GAS → Worker の順**）:
