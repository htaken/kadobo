# 要件定義 v1.0 統合レビュー（Claude × Codex）

作成日: 2026-08-27 ／ 対象: `docs/archive/稼働記録・経費管理システム_要件定義_v1.0.md`（レビュー時はプロジェクトルートの `_v1.md`。行番号は同一）
レビュアー: Claude（Fable 5）、Codex CLI 0.150.1（独立実行、生出力は `codex_review_v1.0.md`）

## 結論

- 構成（Slack → Worker 即ACK → GAS 本体）は両者とも妥当と判断
- **稼働記録 MVP は Go**。ただし Worker の責務・GAS 認証方式・状態機械の3点は実装前に修正が必要
- **経費の電帳法適合は現設計では不成立**。経費機能が揃うまでは「紙レシートは紙原本保管、電子取引は元データを Drive 保管」の暫定運用にする

## E. 見解の調整（Codex 提案のうち採用を見送る／縮小するもの）

- **耐久キュー（Cloudflare Queues＋DLQ）**: 当初「過剰」と判断したが、「GAS 失敗→押し直し」はエラー見落とし→打刻欠落に繋がるという懸念（2026-08-27）を受け、軽量版を採用。Worker が D1 に受付ジャーナル（冪等キー・`action_ts`）を書いてから GAS へ転送し、Cron Trigger で未完了分を自動再送する。ユーザーの押し直しは不要、打刻時刻は `action_ts` なので再送でもズレない（§F）
- **入金消込の矛盾（17 vs 76）**: 行 76 は MF 銀行連携での手動消込を指すため矛盾ではない。用語の明確化のみ
- Codex 総評「条件付き No-Go」は経費の電帳法適合を指しており、稼働記録 MVP の Go とは両立する

## 実装前に必ず決める事項（トップ5）

1. **Worker の責務範囲**: 署名検証・ACK・`views.open`・同期バリデーション・ホワイトリスト・失敗通知。GAS 認証は本文 HMAC＋timestamp
2. **状態機械と冪等性の遷移表**: 複数セッション、休憩中終了、跨日、二重押下、`CORRECTION` イベント、締め後修正
3. **証憑保存方式**: 紙原本保管（スキャナ保存を選択しない）か適合サービス採用か。証憑区分、保存期間、法定帳簿の正
4. **契約・税務条件**: 70% 経過措置を踏まえた単価、税込/外税、源泉徴収、丸め、締め・支払日、フリーランス法、指揮命令を避ける実運用
5. **月次締めと障害運用**: 締めロック、MF 重複防止、OAuth 更新、失敗通知、バックアップ・復元

## F. 打刻の到達保証（2026-08-27 追記）

懸念: GAS 側の失敗で「押し直し」が必要になると、エラーの見落とし → 打刻欠落に直結する。
方針: **押した事実は Worker 側で先に永続化し、GAS への反映は自動再送で保証する。ユーザーは押し直さない。**

```
ボタン押下
  │
  ▼
Worker: 署名検証
  ├─ D1 に受付ジャーナル INSERT（冪等キー = user_id+message_ts+action_id+action_ts, 状態=pending）
  ├─ 即 ACK（200）
  └─ waitUntil:
       ├─ chat.update → カードに「⏳ 開始 09:02 記録中…」（Worker は payload の channel.id / message_ts を持つ）
       └─ GAS へ POST（タイムアウト 20s）
            ├─ 成功 → D1 状態=done。GAS 側が chat.update で確定表示
            └─ 失敗 → D1 状態=pending のまま。カードを「⚠️ 記録待ち（自動再試行中）」に

Worker Cron Trigger（5〜10 分毎）
  └─ D1 の pending を GAS へ再送（冪等キーで重複排除）
       ├─ 成功 → done
       └─ N 回連続失敗 → 本人へメンション通知（手動確認用リンク付き）

GAS 22:00 トリガー（既存）
  └─ 「稼働中のまま」＋「pending が残っている」を検知して通知（最終セーフティネット）
```

- 打刻時刻は Slack が付与する `action_ts`（押下瞬間）を使う。再送・遅延処理でも時刻はズレない
- GAS の処理は「生ログ 1 行追記 → chat.update」に限定（通常 1〜3 秒）。GAS 自体の 6 分制限には届かず、リスクは一時障害・コールドスタートと Worker `waitUntil()` の 30 秒上限のみ
- D1 はジャーナル用途（保持 30 日程度）。記録の「正」は引き続きスプレッドシート
- 費用: D1（Free: 書込 10 万行/日）、Cron Triggers（Free）とも無料枠内。KV でも代替可だが「pending 一覧」を取るなら D1 が素直
- 「⏳」表示のまま残る＝異常、が視覚的に分かるので、カードを見れば失敗に気付ける
